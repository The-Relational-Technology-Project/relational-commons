# Build: A Front-Porch Digest for One Block

> A starter build: fork Front Porch Forum's constitution, not its code — real names, one geography, one email a day, a rotating neighbor-moderator.

Front Porch Forum's software is proprietary, but its constitution is four rules, and the studied effects (members more likely to volunteer, attend local events, and talk to neighbors) flow from the rules, not the code. Build the rules:

1. **Real names, real addresses.** Members are verified neighbors — by the moderator knowing them, which at block scale is the whole verification system.
2. **One geography.** This digest serves these three blocks. There is no 'nearby areas' toggle. Growth means helping the next three blocks start their own.
3. **One send a day.** Posts queue; the digest goes out at 6pm; nothing is urgent by design. (Actual emergencies have actual channels.)
4. **A human moderator.** A neighbor — rotating quarterly so it stays a chore shared, not a fiefdom — reads everything before it ships, and knows the difference between a hard conversation and a harmful one.

The build: a submission form (email-in works too), a queue the moderator approves, a daily digest email, and a public archive page. Posts are the FPF genre mix: borrowed ladders, lost cats, contractor recommendations, meeting announcements, thanks.

Constraint: resist every feature that makes it faster. The pace is the product. If a neighbor asks for push notifications, the correct response is a porch conversation.

- **guardrails:** the pace is the product — one send a day, moderation rotates, growth means seeding new digests, not expanding this one
